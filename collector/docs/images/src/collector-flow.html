How the collector runs

Ten steps, each one approved on its own. Five write nothing at all, and the five that do are reversed by step 8. The agent prints what a step will do before it does it, and will not start until the exact phrase comes back. An approval never carries to the next step.

The steps 5 read only 5 write
0
Preflight
reads only
Is this account eligible, do you hold the roles, and what is the quota before anything moves
1
Discover
reads only
Which management groups and quota groups exist now. Writes the run configuration every later step reads
2
Read a group
reads only
What the group APIs return, field by field. Against a group that already holds quota this answers most of the file
3
Create a group
writes
Can a group be created by API, what is groupType, and what does enforcement take
4
Fill the group
writes
Does moving idle quota out of a subscription work with no support ticket. Lowers the donor's limit
5
Allocate
writes
The operation vending depends on. Is limit absolute or a delta, how long does it take, and when does Microsoft.Compute agree
6
Failure modes
writes
What the refusals look like, verbatim. Every case is expected to fail; one that succeeds is the finding
7
IaC reachability
plan only
What Terraform's azapi provider will accept. Never applies
8
Teardown
writes
Puts every changed family back to the step 0 baseline and removes the group. Safe to run at any point
9
Package
local only
Redacts every identifier, hashes each file, and produces one zip to send back
Every write is approved on its own
The agent prints the resolved subscription and management group names, not placeholders, so the approval is for the real thing. yes, ok and approve are not the phrase.

What makes it reversible
Step 0 records every family limit on both subscriptions before anything is touched. Step 8 works from that baseline, so it does not care which steps ran or whether one failed halfway. Compare-Baseline.ps1 answers “is it back” at any point, including days later.

The agent may only run the scripts in scripts/. It cannot write a new one, cannot edit one to make a call succeed, and cannot run az directly. A step that needs something no script does is reported as a finding and stops.

Quota is not capacity. Lowering a subscription's limit does not stop a running virtual machine. It stops that subscription creating new ones above the lowered limit.
Steps 0 to 2 write nothing, so the whole shape of the thing can be seen before any write is approved. Stopping after any step still produces a useful package: step 9 records which steps ran, and a question nobody reached is recorded as a gap rather than left blank.
